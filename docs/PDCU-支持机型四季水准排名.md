# PDCU 四季移植：支持机型水准排名（2026-10）

日期：2026-10-28

范围：工具/内置数据目前支持的 **14 台机身**（KF 计入）。
判据：四季数据来源 → 端到端验证强度 → 风格残差；排名是分档的，同档内的名次差异
小于一个 Q13 LSB，不构成可见差别。

## 0. 结论

14 台全部可用，四季风格与 KF 原生的残差都在 **0–7.3×10⁻⁵**（≤0.60 个 Q13 LSB）。
差别不在“四季像不像”，而在“这份四季数据有多可信”：

| 档 | 含义 | 台数 | 占比 |
|---|---|---:|---:|
| **S** | 原生机内四季数据 / 与 KF 基础矩阵逐字节相同的等价原生 | 3 | 21% |
| **A** | 用机身自己的 0x021B 基准精确校准 | 7 | 50% |
| **B** | 没有 0x021A/0x021B，用 ColorMatrix2 推算 | 4 | 29% |

## 2. 为什么这样分档

### S 档：原生或等价原生（3 台）

- **KF**：四季表就是从 KF 机内读出来的，是全部对比的基准。
- **K-70**：KF 与 K-70 共用同一套 21 个基础矩阵（逐字节相同），Y=I，
  写进去的四季矩阵就是 KF 原值；残差 0，属于“等价原生”。
- **K-1**：用的是 K-1 自己的机内四季表，不是 KF 数据。它的 7.3×10⁻⁵ 是
  “两张原生表之间的量化差”，不是移植误差。

### A 档：机身 0x021B 基准精确校准（7 台）

这 7 台都有 `0x021B` 基准矩阵，工具运行时算 `Y = inv(M_KF[0])·M_body[0]`，
再把 KF 四季矩阵乘上 Y。数学上就是 Pentax 生成各机身表的做法，所以是“精确解”。

- **K-3 / K-3 II / K-5 II / K-5 II s**：四台的基准矩阵相同或逐字节相同，
  共用同一个 Y；K-5 II 两兄弟的四季表与 K-3 是同一张表。前两台的缺口最小，
  K-5 II 两兄弟唯一缺的是 PDCU 实测。
- **KP**：自己的 Y，CM2 复核 pass，九机实测。
- **K-S2 / 645Z**：实际渲染仍以 0x021B 为准，四季是精确的；但它们的 DNG
  ColorMatrix2 与自身 0x021B 基准不一致（1.3×10⁻² / 2.7×10⁻³），
  CM2 复核会告警，所以排在 A 档末尾。

### B 档：ColorMatrix2 推算（4 台）

这 4 台没有 `0x021A`/`0x021B`，Y 只能由 DNG 的 ColorMatrix2 反推：

| 机型 | Y 与 K-3 的差 | 说明 |
|---|---:|---|
| K-01 | 1.50×10⁻⁵ | 离单反校准线最近 |
| K-30 | 2.19×10⁻⁵ | 与 K-01 只差 2 个 Q13 系数 |
| K-50 | 3.65×10⁻⁵ | 与 K-3 的 Y 差 3.65×10⁻⁵；端到端验证最完整 |
| Q7 | 0.34（矩阵元素） | 1/1.7" 小底，不在单反校准线上，最佳推算 |

B 档的四季表彼此只差 2–3 个 Q13 系数（≤1 LSB），所以效果上互不吃亏；
排序主要看“推算锚点”和“验证强度”：K-50 有同场景九机实测与 K-3 渲染对照，
排 B 档第一；K-01/K-30 只有渲染复核；Q7 的 Y 离单反线太远且没有第二份
Q7 样本可交叉验证，排最后。

## 4. 边界

1. **同档内的名次不构成可见差别。** 所有残差都 < 1 LSB，档内顺序只是“证据
   完整度”的排序，不是画质排序。
2. **K-5 II / K-5 II s 还没在 PDCU 里实测**（当时的分析机没装 PDCU），
   它们的数据与 K-3 共用同一张表；如果只看“已实测”，这两台应单独标注。
3. **K-30 / K-01 没有同场景定量色差**，样本是街景/舞狮；本次只用当前表
   重新渲染确认 PDCU 列出并渲染四项。
4. **Q7 是“最佳推算”**，不是官方数据；1/1.7" 小底的色彩空间与单反差得远，
   即使九机实测一致，也不能证明 Pentax 会给 Q7 做同样的四季。
5. **只验证 PDCU 5.10.2.2**；Lightroom / Capture One / dcraw 不读 Pentax 四季。
